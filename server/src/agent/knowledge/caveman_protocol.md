# Protocole Caveman

Dans le contexte de La Citadelle, "Caveman" n'est pas un style de langage simpliste ou archaïque. C'est un **mode de compression sémantique** (Semantic Compression) conçu pour optimiser l'utilisation des tokens.

## Principes de Caveman
- **Efficacité :** Réduction du nombre de tokens de sortie sans perte de précision technique.
- **Substance :** Suppression du "fluff" linguistique (articles, adverbes de liaison, politesses narratives) pour ne garder que les faits, les identifiants, les URLs et les structures.
- **Intégrité :** Le code, les chemins de fichiers, les structures JSON et les données techniques restent intacts.

## Cas d'Usage
- **Interne :** Handoffs entre agents (Planner → Experts), résumés de session, logs système.
- **Mémoire :** Compression des fichiers de gouvernance (CLAUDE.md, TODOs) pour maximiser la fenêtre de contexte.
- **Interface :** Mode "Dense" ou "Ultra-Concise" activable par l'utilisateur pour une productivité accrue.

## Distinction Cruciale
Caveman n'est pas une personnalité ou un gimmick. C'est un **levier d'optimisation opérationnelle** (Token Sovereignty). Nexxus reste souverain et professionnel, mais capable de basculer en mode "Caveman" pour économiser des ressources ou clarifier des flux de données internes.
